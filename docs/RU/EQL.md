### Применение и примеры
Аббривеатура **EQL** расшифровывается как **ECS Query Language**, то есть язык запросов к **ECS** *(Entity-Component-System)*.  

Его синтаксис напоминает **SQL**, и в целом он читается как обычный английский.  

В будущем, в языке будет присутствовать всё возможное для взаимодействия с движками **ECS**, включая Выбор каких либо сущностей, их изменение, добавление новых компонентов и прочее. По мере разработки документация будет дополняться.  

Рассмотрим пример запроса, который выберет все сущности, имеющие компонент `Position`, но не имеющие компонент `Dead`:
```EQL
SELECT WITH Position WITHOUT Dead
```

Здесь есть ключевое слово `SELECT`, означающее операцию выбора сущностей и фильтры `WITH` и `WITHOUT`, означающие компоненты, которые сущность Должна или Не должна иметь.  

Все ключевые слова **регеистрозависимы** и должны писаться **КАПСОМ**.  

Токены **разделяются по пробелам** (Включая обычный пробел ' ', табы, переносы строки и др.)

### Типы операций
Типы операций ставятся перед запросом и означают что нужно сделать и какой тип результата мы получим на выходе.

В текущей версии существует только тип операции `SELECT`. Он означает, что в результате мы получим массив каких либо сущностей, подходящих по переданным фильтам.  

В ближайшем будущем планируется добавить `SET` - Установку значения какого либо компонента у сущностей к определенному значению, и `GET` - Получение значения какого компонента у сущностей.  

При этом можно писать несколько типов в одном запросе:
```EQL
SELECT WITH Position SELECT WITHOUT Dead
```

Вернет результат первого и результат второго `SELECT` в одном массиве.

### Фильтры выбора
Фильтры относятся к операции `SELECT`. С их помощью мы указываем, какие сущности мы хотим получить. В текущей версии содержится 2 фильтра.  

`WITH` - Выбираемые сущности Должны иметь какой либо компонент.  
`WITHOUT` - Выбираемые сущности Не должны иметь какой либо компонент.  

Можно указывать много компонентов за раз в один фильтр:  
```EQL
SELECT WITH Position Velocity
```
Выберет сущностей с `Position` и с `Velocity`

При этом пустые фильтры вернут ошибку, а не всех сущностей:
```EQL
SELECT WITH // Ошибка
```

В будущем для выбора всех сущностей будет добавленно специальное ключевое слово `ALL`.

### Логические операторы
В языке существуют логические операторы AND и OR. Они ставятся между фильтрами.  

`AND` - Означает, что сущности должны подходить и по левому, и по правому фильтру. например:
```EQL
SELECT WITH Position AND WITHOUT Dead
```

Выберет только сущностей с компонентом `Position` И без компонента `Dead`.  
Причем операторы AND автоматически подставляются между двумя фильтров, например
```EQL
SELECT WITH Position WITHOUT Dead
```
На уровне парсера превратится в
```EQL
SELECT WITH Position AND WITHOUT Dead
```  

`OR` Означает, что сущности должны подходить либо по левому, либо по правому фильтру. например:
```EQL
SELECT WITH Position OR WITH Movable
```

Выберет сущностей у которых есть хотя бы один из этих компонентов.  

**На данный момент в языке нету приоритета операторов.** Кто первее стоит, тот первее и учтется. Это стоит учитывать при использовании вложенных операторов. Возможно позже появится приоритет либо круглые скобки как часть синтаксиса для его ручного выставления.
